## Scope

This threat model covers the Git ID Switcher VS Code extension. The extension manages Git identities (name, email, SSH authentication keys, and commit signing keys: a GPG key ID or an SSH key) and interacts with external binaries (`git`, `ssh-add`, `ssh-keygen`) via child processes.

### Authentication Key and Signing Key

An identity can name two different SSH keys, and they carry different risks:

| Key                | Field               | What it proves                                     | How the extension uses it                                                                                 |
| ------------------ | ------------------- | -------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Authentication key | `sshKeyPath`        | Access to a remote (push, pull)                    | Added to ssh-agent when `autoSwitchSshKey` is on, after the keys of the configured identities are removed |
| Signing key (SSH)  | `sshSigningKeyPath` | Authorship of a commit, shown as verified by hosts | Written to `--local` `user.signingkey` with `gpg.format ssh`; never added to ssh-agent                    |
| Signing key (GPG)  | `gpgKeyId`          | Authorship of a commit, shown as verified by hosts | Written to `--local` `user.signingkey` with `gpg.format openpgp`                                          |

A wrong authentication key fails at the remote. A wrong signing key succeeds silently: the commit carries a verified signature of a key the user did not mean to use. The signing key is therefore taken from a narrower source (the identity in user settings with the same `id`, `name` and `email`) than the rest of the identity.

### Safety Invariants

A switch is safe when it keeps these five invariants. A finding is a defect when it breaks one of them:

| ID  | Invariant                              | Meaning                                                                                                      |
| --- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| I1  | Never sign with the wrong key          | Commits are never signed with a key the user did not name for the identity in user settings                  |
| I2  | Never break what belongs to the user   | Git config values the extension did not write, and ssh-agent keys it did not add, are not removed or changed |
| I3  | Never report a failure as a success    | When the intended state is not reached, the user is told                                                     |
| I4  | Never hand authority to the workspace  | A repository cannot choose the signing key, and cannot make the extension write outside `--local`            |
| I5  | Never leave a half-done state silently | When a switch stops part way, the user is told what was left                                                 |

### Threats in Scope

The extension defends against a **malicious repository** (its workspace settings, and the values in its `.git/config` that the extension reads and writes) and against **mistakes of the user** (a wrong path, a stale `.pub` file, a value set by hand). Another OS user on the same machine is in scope as a mistake of the user: someone who works in several accounts can widen the permissions of a key file from another one, so key files that group or others could change (or, for a private key, read), or that another user than the current one or root owns, are refused (Unix).

**Other processes running as the same OS user are out of scope**: replacing key files, replacing the ssh-agent socket, or changing git config while a switch runs. A process with that access can do the same things without the extension. Such cases are not defended against; they are listed below as limits.

### Limits

- **Git config changed during a switch**: Each key is read once before a switch writes it. A change made by another process (a terminal, another VS Code window) between that read and the write is overwritten, and a rollback after a failed write puts back the values read at the start, also over such a change
- **Two windows**: Switches run one at a time within one VS Code window only; two windows switching the same repository at once are not serialized
- **A window closed part way**: If VS Code stops while a switch is writing, the values written so far stay, and the stored record still describes the earlier state. The extension then treats them as the user's values and never removes them automatically (I2 over cleanup). Sync Check, when it is on, reports a mismatch only where the values written differ from those of the identity still current; signing values written while the current identity has no signing key and its repository has no record are not reported
- **Signing key checked once per file version**: The signing key is checked when its file, or the `.pub` file next to it, has changed (path, size, modification time and permissions) since the last check that passed. A file replaced with the same size and modification time, a key removed from ssh-agent later, or a change made between the check and a commit is not seen
- **Key file replaced between the check and its use**: The key file is checked, then git reads it again at each commit. Another process replacing it in between is not caught
- **Key file permissions on Windows**: The permission and owner checks of key files run on Unix only; Windows ACLs are not checked
- **Config that overrides `--local`**: A value in `config.worktree`, or in a file included from the repository's config, can take precedence over the `--local` value the extension writes. Sync Check compares the value git uses and reports this, but with Sync Check turned off the user is not told
- **ssh-agent socket**: The ssh-agent the signing check talks to (`SSH_AUTH_SOCK`) is trusted to be the one git will use
- **A private key with a passphrase**: Its public key cannot be read without the passphrase, so it is not accepted as `sshSigningKeyPath`; the public key file (`.pub`) with the private key in ssh-agent is
- **Authentication keys in ssh-agent**: Switching removes the authentication keys of all configured identities by path, then adds the selected one. The key the selected identity signs with (`sshSigningKeyPath`, or the private key of its `.pub` file) is not removed, even when it is another identity's authentication key. A key of a configured identity that the user added by hand is removed too: a known gap against I2
- **Global config**: `--global` and system config are never written or put back, so an identity without a signing key signs if the user's global config says so
- **The repository's own `.git`**: Once the workspace is trusted, its `.git` can run programs through git (hooks, `core.fsmonitor`, `gpg.ssh.program`) and redirect config (`include`, or a `.git/config` that is a symbolic link: git writes `--local` values through the link to the file it points to, such as `~/.gitconfig`). The extension writes and checks the `--local` file only, and checks a signing key with its own `ssh-keygen`, not the program git is told to use; Sync Check compares the value git uses

## Spoofing (S)

### S1: Git Identity Forgery

| Aspect                   | Detail                                                                                                                                               |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Threat**               | Attacker modifies Git identity to impersonate another developer                                                                                      |
| **Attack Vector**        | Malicious workspace settings override identity config                                                                                                |
| **Existing Mitigations** | VS Code Workspace Trust integration; extension enters restricted mode in untrusted workspaces; identity changes are logged via security audit logger |
| **Residual Risk**        | Low — trusted workspaces can modify identity by design                                                                                               |

### S2: SSH Key Substitution

| Aspect                   | Detail                                                                                                                                                                                                                                                           |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Threat**               | Attacker replaces SSH key path to load a malicious key                                                                                                                                                                                                           |
| **Attack Vector**        | Modified `sshKeyPath` in configuration                                                                                                                                                                                                                           |
| **Existing Mitigations** | Path validation pipeline (null bytes, traversal, symlinks, control chars, invisible Unicode incl. Bidi override — CVE-2021-42574); SSH key basename exact-match; key file type/size/permission validation; regular files only                                    |
| **Residual Risk**        | Very low — multi-layer path validation blocks traversal, symlink, and Trojan Source attacks; SSH key matching is exact. Key paths may be outside `~/.ssh/` (and on Windows a drive path), so the path and file checks, not the directory, are what accept a path |

### S4: Signing Key Substitution

| Aspect                   | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Threat**               | Commits are signed with a key the user did not choose for that identity                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Attack Vector**        | Signing key fields (`gpgKeyId`, `sshSigningKeyPath`) supplied by settings other than the user's own                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Existing Mitigations** | Signing keys are read from user settings only, from the identity with the same `id`, `name` and `email`; a value from other settings, or a user identity with the same `id` but another name or email, is ignored and logged; the identity screens start every write from the user settings, so a workspace's identities (signing keys included) are never moved into them, and an identity defined only in workspace settings is not edited there; `gpgKeyId` and `sshSigningKeyPath` are mutually exclusive (schema and form), and an identity whose user signing keys are invalid or set both is skipped, never applied without signing; before git is told to use an SSH signing key, the key signs a short test text as git signs a commit (`ssh-keygen -Y sign -n git`, without an askpass program and with a 30 second timeout), and the switch stops unless the signature is made and the key in it is the one the setting names (read with `ssh-keygen -y` from a private key, or from a public key file) — which key OpenSSH picks (a `.pub` file next to the key, a key in ssh-agent) is not predicted, the signature says; before that, the path must be absolute on the platform, the key file a regular file of a key's size, and the key file and the `.pub` file next to it owned by the current user or root and with the permissions of a key (Unix: a private key not accessible by group or others nor executable, a public key not writable by group or others nor executable — the rules of an authentication key; Windows ACLs are not checked); the key is never added to ssh-agent; Sync Check reports a mismatch of `gpg.format`, `user.signingkey` or `commit.gpgsign`, in the value git uses and in the repository's `--local` config |
| **Residual Risk**        | Low — user settings are trusted by design. A workspace can still pick which of the user's identities applies, by an `id` whose name and email match the user's identity, so a repository can get that identity's own signing key without the user choosing it there; it cannot pair a key with another name or email. The check runs only when the key file has changed (see Limits)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

### S3: Extension Impersonation (Typosquatting)

| Aspect                   | Detail                                                                                                                                                                                                                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Threat**               | Attacker publishes a fake extension with a similar name to trick users into installing it                                                                                                                                                                                 |
| **Attack Vector**        | VS Code Marketplace / Open VSX typosquatting (similar publisher name, extension name, or icon)                                                                                                                                                                            |
| **Existing Mitigations** | Cosign keyless VSIX signing (users can cryptographically verify authenticity); SLSA Level 3 build provenance; README fingerprint section (Publisher ID, Extension ID, repository URL); SECURITY.md typosquat reporting procedure; CI-enforced package.json URL validation |
| **Residual Risk**        | Medium — most users do not verify signatures; Verified Publisher badge planned for additional visual trust signal                                                                                                                                                         |

## Tampering (T)

### T1: Configuration File Tampering

| Aspect                   | Detail                                                                                                                                                                                                                                                                                              |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Threat**               | Attacker modifies VS Code settings to inject malicious config                                                                                                                                                                                                                                       |
| **Attack Vector**        | Direct modification of `.vscode/settings.json`                                                                                                                                                                                                                                                      |
| **Existing Mitigations** | JSON schema validation (`configSchema.ts`); field length limits; type enforcement; identity duplicate detection at schema + runtime; prototype pollution defense (`__proto__`, `constructor`, `prototype` keys rejected via `Object.hasOwn()`); signing keys taken from user settings only (see S4) |
| **Residual Risk**        | Low — VS Code Workspace Trust gates untrusted workspace settings                                                                                                                                                                                                                                    |

### T2: Command Argument Injection

| Aspect                   | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Threat**               | Attacker injects malicious arguments into git/ssh commands                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Attack Vector**        | Crafted identity fields (name, email) containing shell metacharacters                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Existing Mitigations** | `execFile()` bypasses shell interpretation; strict command allowlist; argument count (max 20) and length (max 256) limits; flag injection prevention; flag validator rejects unsafe characters; `git config` arguments matched as a whole against per-key rules for operation, scope and value (writes only with `--local`; `--global` and writes without a scope rejected); `ssh-keygen` arguments matched against its three forms (`-lf`, `-y -P ''`, `-Y sign -n git`), and its standard input to the fixed test text for `-Y sign` (none for the other forms); Windows drive paths get the same path checks for `git config` and `ssh-keygen` |
| **Residual Risk**        | Very low — `execFile()` + allowlist eliminates shell injection                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

### T3: VSIX Binary Tampering

| Aspect                   | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Threat**               | Supply chain attack replaces legitimate VSIX with malicious version                                                                                                                                                                                                                                                                                                                                                                         |
| **Attack Vector**        | Compromised marketplace, CDN, or download source                                                                                                                                                                                                                                                                                                                                                                                            |
| **Existing Mitigations** | SLSA v1.0 Build Level 3 build provenance, verified by the publish jobs before anything is shipped (from 0.19.9); Cosign keyless VSIX signing (failure blocks release); Harden Runner egress-policy `block` on the build and publish jobs with explicit allowed-endpoints; Trivy pre-publish scan; CycloneDX SBOM (attested when the attestation step succeeds); `pnpm audit` gate in CI that fails on a known vulnerability of any severity |
| **Residual Risk**        | Very low — cryptographic verification available via `cosign verify-blob` and `gh attestation verify`; egress blocking limits exfiltration during build                                                                                                                                                                                                                                                                                      |

### T5: Repository Signing Config Left Behind or Overwritten

| Aspect                   | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Threat**               | After switching to an identity without a signing key, commits are still signed with the previous identity's key; or the user's own signing config is lost                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Attack Vector**        | Values written by the extension staying in `--local` config; a switch that fails part way; two switches writing at once                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Existing Mitigations** | The extension records, per repository, the values it found and the values it wrote (VS Code workspace state) and puts them back for an identity without a signing key; the three keys (`gpg.format`, `user.signingkey`, `commit.gpgsign`) are put back only together and only if none was changed by hand; only these three keys can be unset; every key is read before anything is written, and a failed read is never treated as "not set" (a read with a warning from git, or a value that is not valid UTF-8, is a failed read); a value that could not be written back later stops the switch instead of being overwritten; a failed write puts back the earlier writes in reverse order, and the error says whether all of them were put back; when putting back is not complete, the record is rebuilt from the values found, or dropped when they are a mix; a record that cannot be saved puts the writes back the same way and fails the switch; a `git config --unset` that exits 5 (no single line matched) is confirmed by reading the key again; switches run one at a time within one VS Code window; Sync Check reports leftover values as a mismatch, in the repository and in submodules with a record |
| **Residual Risk**        | Low — the record belongs to the workspace that wrote it, so values written from another workspace or by a version without a record are treated as the user's and are not put back; `user.name` and `user.email` are never unset, so one that was not set before a failed switch stays written (the error says some values could not be put back); other processes and other windows are out of scope (see Limits)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

## Repudiation (R)

### R1: Identity Switch Denial

| Aspect                   | Detail                                                                                                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Threat**               | User denies having switched Git identity                                                                                                                                                   |
| **Attack Vector**        | No audit trail of identity operations                                                                                                                                                      |
| **Existing Mitigations** | Security audit logger records `IDENTITY_SWITCH`, `SSH_KEY_LOAD`, `SSH_KEY_REMOVE`, `CONFIG_CHANGE` events with timestamps; dual logging to Output Channel + file; sensitive data redaction |
| **Residual Risk**        | Low — file logging is opt-in; Output Channel logs are ephemeral                                                                                                                            |

## Information Disclosure (I)

### I1: SSH Key Path Leakage

| Aspect                   | Detail                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Threat**               | SSH key filesystem paths exposed in logs or error messages                                                                                                                                                                                                                                                                                                                |
| **Attack Vector**        | Verbose error messages, debug logs                                                                                                                                                                                                                                                                                                                                        |
| **Existing Mitigations** | `sensitiveDataDetector.ts` redacts paths in logs; `MAX_LOG_STRING_LENGTH` truncation; `redactAllSensitive` mode for maximum privacy; path sanitization in security logger; tooltips show only the file name of `sshKeyPath` and `sshSigningKeyPath`, and Sync Check shows only the file name (or the last 8 characters of a GPG key ID) of a mismatched `user.signingkey` |
| **Residual Risk**        | Low — paths visible in VS Code settings by design (user's own data)                                                                                                                                                                                                                                                                                                       |

### I2: GPG Key ID Exposure

| Aspect                   | Detail                                                                                                                          |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| **Threat**               | GPG key IDs leaked through logs or UI                                                                                           |
| **Attack Vector**        | Status bar display, notification messages                                                                                       |
| **Existing Mitigations** | GPG key IDs are intentionally displayed (they are public identifiers); sensitive data detector masks longer secret-like strings |
| **Residual Risk**        | Accepted — GPG key IDs are public by design                                                                                     |

## Denial of Service (D)

### D1: Resource Exhaustion via Identities

| Aspect                   | Detail                                                                                                                 |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| **Threat**               | Attacker creates thousands of identities to exhaust memory                                                             |
| **Attack Vector**        | Malicious workspace configuration                                                                                      |
| **Existing Mitigations** | `MAX_IDENTITIES` limit (hardcoded, not configurable); field length limits on all string fields; icon byte length limit |
| **Residual Risk**        | Very low — hardcoded limits prevent abuse                                                                              |

### D2: Command Execution Hang

| Aspect                   | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Threat**               | External binary hangs, blocking extension                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Attack Vector**        | Unresponsive git server, ssh-agent deadlock                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Existing Mitigations** | Command-specific timeouts (git: 10s, ssh-add: 5s, ssh-keygen: 5s, and 30s for the signing check, which may wait for a hardware key); the signing check starts no askpass program, and its timeout stops it if it waits for a passphrase on a terminal; custom `TimeoutError` class; user-configurable timeouts with range validation (1-300s); `ssh-add -D` (bulk key deletion) removed from allowlist — only individual key removal (`-d`) permitted |
| **Residual Risk**        | Very low — all external calls have timeouts                                                                                                                                                                                                                                                                                                                                                                                                           |

### D3: Log File Growth

| Aspect                   | Detail                                                                                                                                                                                                                                                                              |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Threat**               | Log files consume excessive disk space or symlink-based log tampering                                                                                                                                                                                                               |
| **Attack Vector**        | High-frequency operations triggering repeated logging; symlink replacement of log file between check and open                                                                                                                                                                       |
| **Existing Mitigations** | Configurable `maxFileSize` and `maxFiles` with rotation (range-validated: 100KB-100MB, 1-100 files); file logging is opt-in; per-event-type rate limiter (10 events/10s window) prevents log flooding; `O_NOFOLLOW` flag on file open + `fstat()` symlink check (TOCTOU mitigation) |
| **Residual Risk**        | Very low — rotation + rate limiting + symlink protection prevent abuse                                                                                                                                                                                                              |

## Elevation of Privilege (E)

### E1: Command Injection via Shell

| Aspect                   | Detail                                                                                                                                                                                                                                                                           |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Threat**               | Attacker executes arbitrary commands through the extension                                                                                                                                                                                                                       |
| **Attack Vector**        | Shell metacharacters in user input passed to `exec()`                                                                                                                                                                                                                            |
| **Existing Mitigations** | `execFile()` used exclusively (no shell); strict command allowlist (`git`, `ssh-add`, `ssh-keygen` only); binary path resolution prevents PATH pollution; argument validation with allowlisted flags; ESLint `no-restricted-imports` enforces `exec`/`execSync` ban at lint time |
| **Residual Risk**        | Very low — no shell interpretation path exists; lint-time enforcement prevents regressions                                                                                                                                                                                       |

### E2: PATH Pollution

| Aspect                   | Detail                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Threat**               | Attacker places malicious binary earlier in PATH                                                                                                                                                                                                                                                                                                                                                                          |
| **Attack Vector**        | Modified PATH environment variable                                                                                                                                                                                                                                                                                                                                                                                        |
| **Existing Mitigations** | `binaryResolver.ts` resolves absolute paths using system `which`/`where` from hardcoded locations (`/usr/bin/which`, `C:\Windows\System32\where.exe`); resolved paths cached with 30-minute TTL (re-verified periodically); `git.path` setting validated via `git --version` output check; `which` fallback triggers user-visible warning (session-once); ESLint `no-restricted-imports` blocks `exec`/`execSync` imports |
| **Residual Risk**        | Very low — TTL-based cache prevents stale binary paths; `git.path` spoofing detected by version check                                                                                                                                                                                                                                                                                                                     |

### E3: Workspace Trust Bypass

| Aspect                   | Detail                                                                                                                            |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| **Threat**               | Extension operates in untrusted workspace                                                                                         |
| **Attack Vector**        | Opening a malicious repository                                                                                                    |
| **Existing Mitigations** | `workspaceTrust.ts` checks trust status; extension enters restricted mode when untrusted; commands are blocked in restricted mode |
| **Residual Risk**        | Very low — VS Code enforces trust boundary                                                                                        |
